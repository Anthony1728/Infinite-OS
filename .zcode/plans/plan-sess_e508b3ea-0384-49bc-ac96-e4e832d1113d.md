# Implementation Plan: Repairing AI Agent Intelligence and Automation Stability

## Context
A technical audit reveals that while the infrastructure for agentic AI exists (Orchestrator, Brain, Provider abstractions, Memory), reliability is compromised by monolithic IPC handlers in the main process, loss of turn state on crashes, and inconsistent tool schema mapping. The requested "world-class AI operating system" requires stability for core agent workflows (automation, tool calls, phone integration).

## Objectives
1. **Stabilize Core Agent Runtime**: Fix the turn state persistence and tool-call reliability issues.
2. **Automation Reliability**: Repair broken automation triggers and action handlers.
3. **Phone/WhatsApp Connectivity**: Diagnose and fix the WhatsApp bridge communication and turn loop.
4. **Resilience**: Ensure agents can recover from tool-use failures and maintain session context.

## Proposed Changes

### 1. Agent & Automation Reliability (Critical)
- **State Persistence**: Update `runAgent` in `src/main/agent/loop.ts` to checkpoint turn results to `src/main/session/store.ts` more aggressively so crashes don't wipe progress.
- **IPC Handler Decoupling**: Refactor monolithic handlers in `src/main/ipc/automation.ts` and `src/main/ipc/index.ts` to use a dedicated controller/worker model for background automation runs to prevent blocking the UI.
- **Automation Retries**: Implement improved backoff logic in `src/main/automation/builder.ts` for flaky tool calls that rely on external services.

### 2. Messaging & Phone Bridge Fixes (High Priority)
- **WhatsApp Bridge Diagnostic**: Analyze `src/main/messaging/whatsapp-link.ts` and its interaction with `src/main/agent/loop.ts`. The current `shouldAnswerInbound` gate is too restrictive.
- **Connection Recovery**: Enhance the `whatsapp-link` keep-alive and reconnection logic to handle phone-side network drops gracefully.
- **Session Context**: Ensure `whatsapp-link` conversation history correctly bridges into the `sessionStore`.

### 3. Tool Calling & Reasoning (Medium Priority)
- **Schema Validation**: Add rigorous validation for tool inputs in `src/main/agent/tool-execution.ts` before the tool is invoked to prevent cascading errors from malformed JSON in partial tool-use chunks.
- **Thinking Budget**: Adjust thinking-budget configuration for Ollama models in `src/main/providers/registry.ts` to ensure consistent tool execution capability.

## Verification
- **Unit Tests**: Add targeted tests for the `whatsapp-link` turn-answering logic in `src/main/messaging/whatsapp-turn.test.ts`.
- **E2E Stability**: Run a "smoke test" automation that executes a sequence of tool calls (Read/Write/GitStatus) to verify the builder handles retry logic and error recovery.
- **Build Checks**: Maintain successful builds using `npm run build` after every major refactor of the IPC/Agent boundary.

## Estimated Effort
- **Agent/IPC Refactor**: 3 days.
- **WhatsApp Bridge/Automation Fixes**: 2 days.
- **Testing and Verification**: 2 days.

This plan addresses the broken agent functionalities while strictly adhering to the existing codebase's architectural patterns.
